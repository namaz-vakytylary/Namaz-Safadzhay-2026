# Намаз Вакытлары Тест — 1.2-test3

Тестовое приложение устанавливается рядом с оригинальным: `ru.namaz.safadzhay.test`, versionCode 35. Данные и настройки приложений независимы. Основная ветка оригинального приложения не изменяется.

В настройках: «Названия намазов на татарском» / «Показывать рядом с русскими» и «Обновление расписания». Сохранено поведение пятничного баннера: в текущую пятницу он показывается до Асра.

## Расписание

Источник: https://emilzhianshin-dot.github.io/namaz-schedules/manifest.json.

При открытии приложения и наличии подключения автоматическая попытка проверки выполняется не чаще одного раза в 7 дней. Кнопка «Проверить обновления» запускает проверку сразу. Загрузка выполняется в отдельном потоке. Неизменённые файлы повторно не скачиваются.

Все опубликованные годы для Москвы и Сафаджая сохраняются в постоянном хранилище приложения. Проверяются схема, год, даты, часовой пояс, порядок времён, размер и SHA-256. Новые данные заменяют сохранённый снимок только после успешной загрузки и проверки всех изменённых файлов. При ошибке остаётся прежнее расписание; на первом запуске без сети доступно встроенное. Удаление приложения или очистка его данных удалит скачанное расписание.

Встроены исходные 153 дня для каждого города: 1 августа — 31 декабря 2026 года, все 1530 времён сохранены без изменений. Реальное расписание на 2027 год пока не опубликовано. Календарь и сохранённая очередь уведомлений поддерживают загруженные следующие годы. Искусственные примеры будущих дат находятся только в unit-тестах.

Для нового года нужно опубликовать файл по той же схеме и добавить запись в manifest.json. При исправлении существующего года нужно повысить version и пересчитать bytes/SHA-256. Версии ниже уже установленной игнорируются. Расписание должно происходить из проверенного источника; приложение его не рассчитывает.

## Сборка

JDK 17, Android SDK 35, Build Tools 35.0.0.

```sh
python3 scripts/preflight.py
bash gradlew --no-daemon :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease
bash scripts/verify-apk.sh
```

APK: `app/build/outputs/apk/release/app-release.apk`. Рабочий процесс GitHub Actions запускается вручную; выбирать тестовую ветку.

Проверка на физическом телефоне отдельно необходима для системных разрешений, звука, вибрации, компаса и доставки уведомлений в режиме энергосбережения. Автоматические проверки не заменяют эту проверку.
